# Excel VBA Project Template

Excel VBA（VBE）を使うプロジェクトのひな形です。新しいプロジェクトを作るときは、このフォルダーをコピーしてプロジェクト名に変更し、コピー先で作業してください。

## このテンプレートの内容

```text
ProjectName/
├─ README.md          プロジェクトの目的と使い方
├─ .gitignore         Gitに登録しないファイルの指定
├─ Source/            VBEから書き出した本番用VBAソースを置く
├─ Sandbox/           試作・検証用コードを置く（詳細はSandbox/README.md）
├─ ProjectName.xlsm   Excelで作成・保存するマクロ有効ブック
└─ .git/              コピー後に作成するプロジェクト専用Git履歴
```

テンプレートには`.git`とプロジェクト固有の`.xlsm`を含めません。これらはコピー先のプロジェクトで用意します。

## 新しいプロジェクトの準備

1. このフォルダーをコピーし、`Workspace\\Projects`の下に`Project プロジェクト名`として配置します。
2. コピー先にExcelブックを作成し、マクロ有効ブック（`.xlsm`）として保存します。
3. VS Codeでは引き続き`Workspace.code-workspace`またはワークスペース直下を開きます。プロジェクト単体では開きません。
4. VS Codeのターミナルでコピー先のプロジェクトフォルダーへ移動し、そのプロジェクト専用のGitリポジトリを作成します。

```powershell
git init -b main
```

## VBAコードの管理

VBAコードの本体はExcelブック（`.xlsm`）内に保存されます。履歴や差分をGitで確認しやすくするため、VBEから標準モジュール、クラス、フォームをエクスポートし、`Source`以下に保存します。

```text
Source/
├─ ブック名/                         VBAソース
│  ├─ モジュール名.bas
│  ├─ クラス名.cls
│  └─ フォーム名.frm と関連する .frx
└─ .excel-vba-sync-backups/
   └─ ブック名/                      同期管理用のJSON
      └─ モジュール名.syncbase.json
```

取得時は、同じブック名のフォルダーが `Source/` 直下と `Source/.excel-vba-sync-backups/` 以下にそれぞれ作成されます。VBAソースは種類別の `Modules/`、`Classes/`、`Forms/` には分けず、`Source/ブック名/` に保存します。ファイルの種類は対象ブックと取得方法によって異なり、シートや `ThisWorkbook` のコードが `.bas` として出力される場合もあります。

`.syncbase.json` には、ソースファイル名、コードのSHA-256ハッシュ、取得元、記録日時などが保存されます。VBAコード本体ではなく、JSONだけではコードを復元できません。フォルダー名が `.excel-vba-sync-backups` でも、添付例のJSONをVBAソースのバックアップそのものとして扱わないでください。

エクスポートしたファイルを編集しただけでは、ブック内のVBAコードは変わりません。編集内容をExcelで使うには、VBEへインポートするか、VBE上で編集した後に改めてエクスポートしてください。ブックとエクスポートしたソースの両方を更新して管理します。

## Copilotの作業記録と引継ぎメモ

このテンプレートには、プロジェクトの記録原本`CopilotActivityLog.md`と、次のチャットへ渡すための選択済みメモ`CopilotMemory.md`が含まれています。両ファイルは作業用のローカルメモとして`.gitignore`で除外し、Gitには登録しません。既存プロジェクトにはそのプロジェクトの`.gitignore`にも同じ除外設定が必要です。既に追跡中のファイルは除外設定だけでは追跡解除されません。ユーザープロンプトのフックは、作成・実装・修正などの作業依頼表現を検出すると依頼文を原本に追記します。自動記録はベストエフォートであり、相談だけの文、明示的な否定、対象プロジェクトを特定できない場合は記録しません。項目は必ず`copilot_context: false`で追加されます。

`Workspace.code-workspace`またはワークスペース直下をVS Codeで開いた状態で、次の共通タスクを使います。対象プロジェクトを選択します（活動ログが1件だけなら自動選択）。

- `Copilot: true項目をメモへ抽出`：原本から`copilot_context: true`の項目だけを`CopilotMemory.md`へ出力します。
- `Copilot: discard項目を確認して完全削除`：削除対象を表示し、`DELETE <件数>`の入力を確認してから原本から削除します。バックアップは作成しません。

状態の変更は人が行います。`true`は次回のチャットで利用する項目、`false`は保留、`discard`は削除予定です。自動記録された項目を確認し、不要な依頼文や秘密情報がないか確認してから状態を変更してください。新しいチャットでは必要な場合に限り`CopilotMemory.md`を参照させ、`CopilotActivityLog.md`全体は渡しません。

ツール・タスク・フックはワークスペース直下の`.tools`、`.vscode/tasks.json`、`.github/hooks/copilot-activity.json`に集約しています。各プロジェクトにはこの機能用のスクリプトや設定をコピーせず、2つのメモファイルを置きます。

VS Code/Copilot側のフック機能が有効である必要があります。フックが動かない場合は、VS Codeを再読み込みし、Copilotのフック対応状況とワークスペースの信頼状態を確認してください。フックの検出ルールはヒューリスティックであり、記録の完全性を保証しません。

### 活動ログの記載形式

Markdownプレビューではなく、エディターでソースを直接読んで状態を編集するときの見やすさを優先します。1つのタスクまたは決定を1件とし、次の形式で追記します（以下は記載例であり、実施済み作業ではありません）。

```markdown
<!-- ==================== メモ開始：CA-YYYYMMDD-XXXXXXXX ==================== -->

## [CA-YYYYMMDD-XXXXXXXX] 作業・決定のタイトル

- copilot_context: false
- 記録日: YYYY-MM-DD

### 決定事項
- 決まった方針や制約を短く記載する。

### 実施内容
- 実際に行った変更を記載する。

### 注意・残作業
- 未確認事項や次に必要な作業を記載する。

<!-- ==================== メモ終了：CA-YYYYMMDD-XXXXXXXX ==================== -->
```

- 開始・終了コメントと見出しのIDを一致させ、項目間には空行を2行入れます。
- 開始コメントは見出しの直前（空行可）に置きます。
- 状態行は見出しの直後付近に1つだけ置き、囲まれたメモ全体に適用します。
- 見出し・説明・本文は日本語とし、長い文章は改行して整理します。本文の小見出しは必要なものだけを使います。
- 共通の説明はファイル冒頭にまとめます。実施内容と未実施・未確認事項は区別します。
- 自動記録フックも同じ開始・終了コメントを付けますが、作業完了ではなく「依頼内容」として記録します。
- 原本は[CopilotActivityLog.md](./CopilotActivityLog.md)です。新しい項目は必ず`false`にし、作業者が確認して状態を変更します。

## Gitで変更を保存

`.gitignore`を確認してから、プロジェクトのファイルをGitに登録します。

```powershell
git status
git add .
git commit -m "Initial project setup"
```

Gitコマンドは必ずコピー先のプロジェクトフォルダーで実行してください。Excelの一時ファイルや秘密情報が登録対象になっていないことも確認します。
