# Excel VBAプロジェクト作成ツール

## 利用に必要な環境

プロジェクト作成にはVS Code標準のタスクとPowerShellを使用します。**このツール専用の拡張機能やインストール作業はありません。** `Install-WorkspaceProjectGitExtension.ps1` の実行や、拡張機能のインストールに伴う再読み込みも不要です。新規Gitリポジトリが自動表示されない場合の再読み込みについては、後述の手順を参照してください。

必要なソフトウェアはGit for Windows、VS Code、Windows PowerShellです。作成したExcel VBAプロジェクトの開発・動作確認にはExcelデスクトップ版も必要です。PowerShellスクリプトの利用は課内のルールに従ってください。

## VS Codeでプロジェクトを作成する

1. `Workspace.code-workspace` またはWorkspace直下のフォルダーをVS Codeで開きます。
2. 「ターミナル」→「タスクの実行」を選びます。
3. `New: Excelプロジェクト新規作成` を選びます。
4. VS Code標準の入力欄でプロジェクト名を入力します。`Sample` と入力すると `Projects/Project Sample` が作成されます。入力をキャンセルすると作成処理は開始されません。不正な名前は作成スクリプトでエラーになります。
5. ターミナルの完了表示を確認します。タスクはGitの初期化・ステージングまで行い、Gitビューに表示されない場合の再読み込み手順を日本語で表示します。作成先をワークスペースフォルダーに追加したり、ワークスペースの構成を変更したりしません。

共通ツールはWorkspace直下の `.tools`、共通タスクと入力欄の定義は `.vscode/tasks.json` にあります。UserFormのCSV出力・反映ツールは[`UserFormCsvExporter`](UserFormCsvExporter/README.md)にあります。Gitの自動検出と検索深度の設定は `.vscode/settings.json` にあります。

### Gitビューでの表示について

新規作成直後の表示はVS Codeの自動検出に任せます。表示されない場合は、次の手順で起動時の再スキャンを実行してください。

1. 編集中のファイルを保存します。
2. `Ctrl+Shift+P` でコマンドパレットを開きます。
3. **「開発者: ウィンドウの再読み込み」（Developer: Reload Window）** を実行します。
4. 再読み込み後、ソース管理のリポジトリ一覧を確認します。

`.vscode/settings.json` の `git.autoRepositoryDetection: true` と `git.repositoryScanMaxDepth: 2` により、ワークスペース直下から `Projects/Project ...` までを起動時にスキャンする構成です。VS Code標準のGit拡張機能が有効で、ワークスペースが信頼されていることが前提です。別の設定で探索先が除外されている場合や、対象リポジトリを明示的に閉じている場合など、再読み込みだけでは表示されないことがあります。

まだ表示されない場合は、コマンドパレットから「Git: リポジトリを開く」を実行し、ターミナルに表示された作成先フォルダーを指定してください。この操作はワークスペースフォルダーの追加ではありません。作り直しや再度のGit初期化は不要です。

タスクは案内を表示するだけで、VS Codeの自動再読み込みやGitビュー内の選択・フォーカスの変更は行いません。案内表示はGitビューへの登録成功を保証するものではありません。

日本語の完了案内は `.tools/New-Project.messages.json` にあります。Windows PowerShell 5.1でも文字化けしないよう、スクリプトがUTF-8を明示して読み込みます。配布時は `New-Project.ps1` と同じフォルダーに同梱してください。案内ファイルの読み込みはプロジェクトを作成する前に行います。

## Copilotの作業記録と引継ぎメモ

Copilotフックは、送信された依頼文に実装・作成・修正などの表現が含まれる場合、対象プロジェクトの `CopilotActivityLog.md` に依頼文を `copilot_context: false` として追記します。相談表現や否定表現などは除外する簡易判定です。フックは会話の結果や実際に作業へ着手したことまでは確認しないため、記録漏れ・誤記録がありえます。`event.prompt` と `event.cwd` を利用し、プロジェクトが特定できない場合は何も記録しません。

依頼文の一部はパスワードやトークンらしい値をマスキングしますが、これは完全な秘密情報検出ではありません。機密情報を含む依頼はログに残る可能性があるため、ログを定期的に確認してください。記録された `false` 項目を人が確認し、必要なものだけ `true` に変更します。メモの見出し・説明・記録日時などの表示とタスクの案内は日本語です。ファイル名、`copilot_context`、状態値（`true`・`false`・`discard`）、削除確認文字列（`DELETE <件数>`）は処理用の表記を維持します。

常に`Workspace.code-workspace`またはワークスペース直下を開いて運用します。ツール・タスク・フックはワークスペース直下に集約し、プロジェクトにはこの機能用のスクリプトや設定をコピーせず、2つのメモファイルだけを配置します。VS Codeのタスクから対象プロジェクトを選んで実行します（活動ログが1件だけなら自動選択）。

- `Copilot: true項目をメモへ抽出` はプロジェクトの `CopilotActivityLog.md` から `true` 項目だけを抽出し、`CopilotMemory.md` を再生成します。
- `Copilot: discard項目を確認して完全削除` は削除対象を表示し、`DELETE <件数>` の入力を確認した後に原本から削除します。バックアップは作成しません。確認文字列が一致しない場合、ファイルは変更されません。

抽出と削除は別のタスクです。項目を `<!-- ==================== メモ開始：ID ==================== -->` と同じIDの「メモ終了」コメントで囲んだ形式にも対応しています。開始コメントは項目見出し `## [ID]` の直前（空行可）に置きます。状態はそのメモ全体に適用され、抽出・削除時には区切りも一緒に扱います。従来の区切りコメントがない項目も使用できます。

新しいチャットには原本全体ではなく、必要に応じて生成した `CopilotMemory.md` を渡してください。タスクとプロジェクトテンプレートへの配置は [`Projects/README.md`](../Projects/README.md) を参照してください。

## PowerShellから直接実行する

PowerShellの実行ポリシーBypassは、作成タスクが起動するプロセスだけに適用します。旧拡張機能のソースとインストーラーは廃止・削除しました。過去にWorkspace Project Gitをインストールした環境では、同名タスクの重複を避けるためVS Codeの拡張機能一覧からアンインストールしてください。Workspace内のファイル削除だけでは、インストール済みの拡張機能は削除されません。

Workspace直下で実行します。標準タスクと同じ作成処理を実行し、ワークスペースへは追加しません。

```powershell
& .\.tools\New-Project.ps1 -ProjectName "Excel Sample"
```

既存の作成先がある場合は、上書きせずエラーで停止します。途中で失敗した場合は、調査できるよう作成途中のフォルダーを残します。内容を確認してから削除するか、別の名前でタスクを再実行してください。
