## 1. 概要・結論

過去レポートには、(1) `D_CallPython.bas` のコード重複によるVBAコンパイルエラー、(2) Ollama起動確認時の実行時エラー438、という別々の不具合が記録されている。前者は `git restore` による復元、後者は `WinHttp.WinHttpRequest.5.1` への置換で対処したとされる。

ただし、本ワークスペースには対象の `D_CallPython.bas`、関連する設定・初期化モジュール、および当時のログが見つからず、記録された原因・修正・検証結果を現行状態と照合できていない。特にエラー438の発生行と原因は未確定である。

## 2. 背景・目的

過去事例として記録された内容を共通ひな形に整理し、確認済みの情報、当時の記録に依存する情報、未確認事項を区別する。後日、対象ソースやExcel環境が確認できた際に、修正の妥当性と現在の状態を再検証できるようにする。

## 3. 対象・影響範囲

- 対象として記録されているファイル・機能：
  - `申請補助/D_CallPython.bas`：Python呼び出し処理および `CheckOllamaRunning()`
  - `申請補助/A_Pubric.bas`：Ollama接続先設定と記録されたファイル名
  - `申請補助/B_Initialize.bas`：初期化処理
  - `申請補助/UserForm4.frm`：「全アプリ詳細」などのAI処理ボタン
- 影響として記録されている内容：重複時はVBAコンパイルが失敗し、Python呼び出し機能が利用できない。起動確認時のエラーでは、Ollama連携機能が停止または誤判定する可能性がある。
- 対象外：`URLGetter.py` のDuckDuckGo headlessタイムアウト事例。別の問題・別のレポートとして扱う。
- 環境・バージョン：未確認。
- 現在のワークスペースでは、上記の申請補助ソースを確認できていない。対象プロジェクトの所在およびブックとの対応関係は未確認。

## 4. 事象・変更前の状態

### 問題1：ソースコードの重複

- 発生条件として記録されている内容：編集後に同一コードが複数回書き込まれた。
- 期待結果：同名のSub／Functionが重複せず、VBAProjectをコンパイルできる。
- 実際の結果として記録されている内容：ファイルが約800行から1254行に増え、`RunAIMode` などが3回ずつ定義され、コンパイルエラー「名前が適切ではありません: RunAIMode」が発生した。
- 重複位置として記録された例：`RunAIMode` は397／774／1151行、`CheckOllamaRunning` は458／835／1212行、`CallAllAppDetailsAI` は510／887／1264行。その他のデバッグ用プロシージャも重複していたとされる。
- これらの行数・定義位置は過去レポートの記録であり、対象ソースとの照合は未実施。

### 問題2：Ollama起動確認のエラー438

- 発生条件として記録されている内容：`DebugCheckOllamaDetailed()` またはUserForm4のAI処理からOllamaの起動を確認する。
- 期待結果：Ollamaが利用可能なら処理を続行し、停止・接続不能なら適切に判定して通知する。
- 実際の結果として記録されている内容：エラー438「オブジェクトは、このプロパティまたはメソッドをサポートしていません」が発生し、起動しているOllamaを未起動と判定するとの報告があった。
- 正確な再現条件、エラー発生行、Ollamaの接続先・稼働状態は未確認。

## 6. 原因・変更理由

### 問題1

過去レポートでは、編集操作によって同じコードが3回書き込まれたことを原因としている。ただし、当時の差分・編集履歴・重複していたファイルを本作業では確認できていないため、現時点では**過去記録上の原因**であり、独立に検証された原因ではない。

### 問題2

**原因未確定。** 過去レポートは `MSXML2.XMLHTTP` の `.Status` 読み込みを原因候補として記載しているが、同レポート自身もその説明に疑問を示している。エラー438の発生行や実際に使われたオブジェクトが確認できていないため、`.Status` が原因とは断定できない。接続・送信時の別の行、実行時のオブジェクトや変数の不一致なども、証拠がないため推測の域を出ない。

また、掲載された修正後コードでは `ErrHandler:` に対応する `On Error GoTo ErrHandler` が確認できない。実ソースにも存在しない場合、通信失敗時にエラー処理へ移れない可能性がある。

## 9. 再発防止・運用上の注意

- VBAソースを変更したら、差分とプロシージャの重複を確認し、対象ブックでコンパイルする。
- `git restore` など変更を破棄する操作の前に、`git status` と `git diff` で未コミット変更を確認する。
- HTTP通信のエラーを調査するときは、エラー番号だけで原因を決めず、実際に停止した行・オブジェクト・エラー情報を記録する。
- エラーハンドラーを設ける場合は、`On Error GoTo ErrHandler` とラベルの対応をソース上で確認し、正常系・通信失敗系の両方を試験する。
- Ollama起動中と停止中の両方で確認する。タイムアウト値や接続先は、実際のネットワーク環境に合わせて検証する。
- エクスポート済みソースの編集はExcelブック内のコードを自動更新しない。ブックとソースの同期手順を対象プロジェクトのREADMEで確認する。
