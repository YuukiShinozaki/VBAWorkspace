## 1. 概要・結論

リポジトリを初めて扱う利用者が、GitHubからZIPをダウンロードした後にクローンを試みたところ、リモート情報取得時にSSL証明書の検証エラーが発生した。

対策として、利用者はVS Codeのターミナルで`http.sslBackend`を`schannel`へ変更した。これはGitのHTTPS通信で使うSSL/TLS処理をWindowsの仕組みに切り替える設定であり、証明書検証を無効にするものではない。

**設定コマンドの実行は利用者報告に基づく。設定後の接続・クローン成功結果は未確認のため、状態は「対応中」とする。** 発生日・対策実施日は未確認であり、上記の日付はレポート作成日である。

あわせて、作業者が初回利用時に確認する設定と、2台目のPCで必要な対応を整理する。ZIPを使わない取得方法と保存先フォルダーの指定は、[ZIPを使用しないリポジトリ取得手順レポート](../Maintenance/20261030_Git_ZIPを使用しないリポジトリ取得手順_レポート.md)へ分離した。

## 2. 背景・目的

GitHubで共有されたExcel VBA開発用ワークスペースを、初めてGitを使う利用者の端末へ導入する際に発生した事例である。

個人の操作ミスと決めつけず、端末の証明書設定とユーザー単位の設定範囲を説明し、初回導入や2台目のPC導入時の設定漏れを防ぐための記録とする。

## 3. 対象・影響範囲

- 取得元：`https://github.com/YuukiShinozaki/VBAWorkspace.git`。
- 影響：GitのHTTPS接続が証明書検証で停止し、リモート情報の取得・クローン作業を進められない。
- 対策対象：Windows端末で、利用者が実行するGitのユーザー単位の設定。
- 本書の対象外：ZIPを使わない取得手順と保存先の指定。これらは別レポートを参照する。
- 未確認：発生端末のGit・Windowsのバージョン、クローン操作に使ったアプリ、Git実行ファイルの場所、社内プロキシや証明書の配布状況。
- 今回の作業はレポート作成と資料確認のみ。端末のGit設定変更、対象リポジトリへの接続確認、ZIP展開、クローン、Excel操作は行っていない。

## 4. 事象・変更前の状態

### 発生経緯（利用者報告）

1. インターネット上のリポジトリをZIP形式でダウンロードした。
2. その後、クローンを試みた。
3. 次のリモート情報取得コマンドで証明書エラーが表示された。

表示されたコマンド：

```powershell
git -c diff.mnemonicprefix=false -c core.quotepath=false --no-optional-locks ls-remote https://github.com/YuukiShinozaki/VBAWorkspace.git
```

提示された出力・エラー：

```text
出力:
エラー: fatal: unable to access 'https://github.com/YuukiShinozaki/VBAWorkspace.git/': SSL certificate OpenSSL verify result: unable to get local issuer certificate (20)
```

`ls-remote`はリモートのブランチ・タグなどの参照情報を取得するコマンドであり、クローンそのものではない。提示ログから確認できる失敗箇所は、このHTTPS接続の段階である。

| 項目 | 期待結果 | 実際の結果 |
| --- | --- | --- |
| リモート情報取得 | GitHubへ接続し、参照情報を取得できる | OpenSSLによる証明書検証が失敗した（提示ログ） |
| クローン | 指定した保存先にリポジトリを取得できる | 利用者報告ではエラーにより作業が停止。クローン本体の実行ログは未提示 |

ZIP取得は経緯の一部であり、ZIPをダウンロードしたこと自体が証明書エラーを起こしたとは判断しない。

## 6. 原因・変更理由

### ログから分かる直接原因

GitのHTTPS通信で使用されたOpenSSLが、接続先から提示された証明書について、信頼できる発行元までの証明書チェーンを構築・検証できなかった。

### 初期設定についての見立て

利用者からは「SSL証明書に関する初期設定をしていなかったらしい」と報告されている。ただし、**証明書検証が失敗した根本原因は未確定**である。エラー文だけでは、必要なCA証明書の不足、CA設定の不整合、社内HTTPS検査の影響などのどれかを特定できない。

Schannelへの切り替えは、Windows側で信頼されている証明書をGitでも利用するための対策となる。証明書を新しく発行・登録するコマンドではなく、すべてのPCで必ず必要な初期設定でもない。Windows側にも必要な証明書がなければ、切り替えだけでは解消しない。

## 7. 対応・変更内容

### 7.1 実施済みの対策（利用者報告）

VS Codeのターミナルで次を実行した。

```powershell
git config --global http.sslBackend schannel
```

| 設定部分 | 意味・注意点 |
| --- | --- |
| `http.sslBackend schannel` | 対応するGitで、SSL/TLS処理にWindowsのSchannelを使用する |
| `--global` | 実行したユーザーのGit設定に保存する。通常、同じユーザーの他のリポジトリにも影響する |
| 端末ごとの適用 | PC間で自動共有される設定ではない。PCが2台ある場合は両方で確認し、この対策が必要で未設定なら、それぞれの端末で実行する |
| ユーザーごとの適用 | 同じPCでも別のWindowsユーザーには自動適用されない。リポジトリのクローンでもこの設定は配布されない |

設定は保存されるため、通常はクローンのたびに繰り返す必要はない。GUIアプリが独自のGitや異なる設定ファイルを使う場合は、VS Codeのターミナル側の変更が適用されるか別途確認する。

### 7.2 作業者初回・2台目のPCでの対応

以下は初回導入時の確認手順であり、各端末で実施済みという意味ではない。

1. Gitを使用するWindowsユーザーで、VS Codeのターミナルを開く。
2. 第8章の設定照会コマンドで現在の設定と適用元を確認し、変更前の値を記録する。
3. この対策を適用する環境で未設定の場合は、第7.1節のコマンドで`schannel`に設定する。すでに正常に接続できる端末へ一律に設定を追加する必要はない。
4. 設定の保存・適用とリモート接続を確認する。GUIを使う場合は、そのアプリでも接続できることを確認する。
5. PCが2台ある場合は、2台目でも同様に確認し、必要な設定を行う。1台目の完了を2台目の完了とみなさない。
6. 接続確認後は、[ZIPを使用しない取得手順](../Maintenance/20261030_Git_ZIPを使用しないリポジトリ取得手順_レポート.md)に沿ってクローンする。

リポジトリごと・クローンのたびに行う設定ではなく、使用する端末・ユーザーごとに初回確認する設定である。未設定でもシステム設定などによりSchannelが有効な場合があるため、ユーザー設定の有無だけで不備と判断しない。

### 7.3 切り戻し

設定変更前に値があった場合は、記録した元の値へ戻す。変更前にユーザー設定がなかったことを確認できる場合だけ、追加した設定を次の方法で解除できる。今回は切り戻しを実行していない。

```powershell
git config --global --unset http.sslBackend
```

解除後はシステム設定やGitの既定動作などに従う。解除すれば必ずOpenSSLに戻るとは限らない。

## 9. 再発防止・運用上の注意

- 作業者の初回導入手順に、使用するGit・設定の適用先・HTTPS接続の確認を含める。取得手順は別レポートを参照する。
- 2台のPCを使う場合は、1台目の設定完了を2台目の完了とみなさず、各端末・利用ユーザーで確認する。
- 証明書エラーが続く場合は、Gitの実行元・設定の適用先と、組織が配布するCA証明書・プロキシ環境を管理担当者に確認する。未知の証明書を安易に信頼登録しない。
- **`http.sslVerify=false`などで証明書検証を無効にして回避しない。** Schannelへの切り替えと、検証の無効化は別の操作である。
- 設定変更前の値と、変更後の接続結果を記録する。正常接続済みの端末に一律の変更を行わない。
