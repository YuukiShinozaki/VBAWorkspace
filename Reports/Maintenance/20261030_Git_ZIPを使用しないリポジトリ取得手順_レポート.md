## 1. 概要・結論

継続的に変更管理する開発環境は、**ZIPをダウンロードせず、GitHubのリポジトリを直接クローンして取得する。** クローン前のZIP取得や、クローン先フォルダーの手作業での新規作成は不要である。

本レポートは取得手順の文書化を対象とし、その整理を完了したものとする。実際のクローンや既存ZIP環境の移行を完了したという意味ではない。今回、端末操作による検証は行っていない。

作業者が初回に行う端末設定とSSL証明書エラーへの対応は、[作業者初回の端末設定レポート](../Defects/20261030_Git_初回クローン時のSSL証明書エラーと端末設定_レポート.md)に分離した。

## 2. 背景・目的

利用者から、リポジトリをZIPでダウンロードした後にクローンを試みたとの報告があった。ZIP取得とクローンを連続した必須手順と誤解しないよう、取得方法と保存先の指定方法を整理する。

証明書エラーへの対策とは目的が異なり、本レポートでは開発環境の取得手順を明確にすることを主目的として`Maintenance`に分類する。

## 3. 対象・影響範囲

- 取得元：`https://github.com/YuukiShinozaki/VBAWorkspace.git`。
- 対象者：このワークスペースを初めて取得する利用者、または別のPCへ導入する利用者。
- 対象範囲：ZIPを使わない取得方法、保存先フォルダー、取得後にVS Codeで開く場所。
- 対象外：Gitの証明書設定、認証・接続障害への対処。これらは関連レポートを参照する。
- 今回変更したのは文書のみ。既存ファイルの削除、ZIP展開、クローン、Excel操作は行っていない。

## 4. 事象・変更前の状態

利用者は、インターネット上のリポジトリをZIPでダウンロードした後にクローンを試みていた。ZIP展開の有無、展開先での編集有無、当時指定したクローン先は未確認である。

| 比較項目 | 変更前の経緯・迷いやすい点 | 整理後の手順 |
| --- | --- | --- |
| 取得方法 | ZIP取得後にクローンを試みた | ZIPを取得せず、直接クローンする |
| 保存先 | フォルダーを先に作る必要があるか分かりにくい | 保存場所のパスと作成するフォルダー名を指定し、Gitに作成させる |
| Git管理情報 | ZIPとクローンの違いを把握しにくい | 履歴・リモート設定を含めて取得するため、クローンを使う |

なお、当時発生したSSL証明書エラーは別の問題であり、ZIPを取得したことが証明書エラーの原因とは判断しない。

## 6. 原因・変更理由

GitHubの「Download ZIP」は選択した時点のファイル一式を取得する方法であり、通常、Gitの履歴を持つ`.git`は含まれない。ファイル参照には使えるが、展開しただけではクローン済みのリポジトリにはならない。

一方、通常の`git clone`ではファイルとGit履歴・管理情報、取得元のリモート設定が用意される。今後の更新取得や変更共有を行う開発環境では、クローンを利用する。ZIP展開先で`git init`を実行しても、元の履歴は取得されない。

## 7. 対応・変更内容

### 7.1 ZIPを使わない取得手順

以下は案内用の手順であり、今回実行した操作ではない。

1. Gitを利用できる状態にし、[作業者初回の端末設定レポート](../Defects/20261030_Git_初回クローン時のSSL証明書エラーと端末設定_レポート.md)で端末設定と接続確認の注意点を確認する。
2. リポジトリのURLと保存場所を決める。ZIPのダウンロードは行わない。
3. VS Codeのターミナルなどで、URLと保存先を指定してクローンする。
4. コマンドが正常終了し、指定先にリポジトリが取得されたことを確認する。
5. 取得した`Workspace.code-workspace`またはワークスペース直下をVS Codeで開く。

例として、`C:\Work`を保存場所とし、その下の`VBAWorkspace`へ取得する場合：

```powershell
git clone "https://github.com/YuukiShinozaki/VBAWorkspace.git" "C:\Work\VBAWorkspace"
```

`C:\Work\VBAWorkspace`は説明用のパスであり、実際の作業先ではない。利用者が使用する保存先へ置き換える。

### 7.2 保存先フォルダーの考え方

- 「置きたい場所のパス＋リポジトリを入れるフォルダー名」を指定する。
- 最後の`VBAWorkspace`フォルダーは、まだ存在しなくてもGitが作成する。先に手作業で作る必要はない。
- 保存場所が利用可能で、フォルダーを作成できる権限があることを確認する。
- 既存フォルダーも使用できるが、空である必要がある。ファイルのある場所への上書き取得ではない。
- GUIでは「親フォルダーを選ぶ欄」と「作成先の完全パスを入力する欄」がアプリによって異なるため、確定前に最終的な保存先を確認する。

### 7.3 すでにZIPを取得している場合

ZIPやその展開先を、そのままクローン元やファイルの入ったクローン先として使わない。別の未使用の場所に直接クローンする。

ZIP側で編集したファイルがある場合は削除せず保全し、クローン後に必要な差分だけを確認して反映する。今回、既存ZIPの削除や編集内容の移行は行っていない。

切り戻し：今回は文書整理のみであり、実環境の切り戻しは該当なし。今後移行する場合も、確認が終わるまで既存ファイルを保全し、未共有の変更があるクローン先を安易に削除しない。

## 9. 再発防止・運用上の注意

- 初回導入時は「ZIPではなくクローン」と案内し、取得方法を混在させない。
- 保存先は未使用の場所を選び、ZIP展開先や既存の開発環境と混同しない。
- 証明書エラーが発生した場合はフォルダー作成やZIP取得で回避しようとせず、関連レポートに沿って端末設定を確認する。
- クローン完了の確認前に、既存の編集済みファイルを削除しない。
